## Why

当前订阅支付闭环只使用 Mock 渠道和自定义 HMAC 回调，无法创建真实交易，也不具备微信支付要求的签名验证、加密资源解密和漏单补偿能力。为使套餐订阅可以在生产环境收款，本期接入微信支付 API v3 普通直连商户 H5 支付，并把回调链路提升为可审计、可恢复的生产实现。

## What Changes

- 使用微信支付官方 PHP SDK 接入普通直连商户 H5 下单，并继续通过现有 `checkout_url` API 字段返回微信 `h5_url`。
- 将支付渠道从写死的 Mock 改为显式配置绑定，同时保留 Mock 供本地开发和自动化测试使用。
- 接收微信支付通知时验证 `Wechatpay-*` 签名头，使用 API v3 Key 解密 AES-256-GCM 资源，并校验商户身份、订单、金额、币种和交易状态。
- 将已验证通知可靠落库后立即返回 HTTP 204，再由队列幂等激活订阅和更新租户套餐。
- 增加主动查单和超时关单任务，为回调丢失、下单结果不确定及未支付订单提供补偿路径。
- 增加支付单创建中状态、支付过期时间、渠道查询时间和脱敏错误字段，以及补偿扫描索引。
- 增加生产配置预检、Secret 文件挂载约束、脱敏日志、失败队列和支付链路监控要求。
- 首期不包含退款、分账、服务商/子商户模式和自动下载平台证书。

## Capabilities

### New Capabilities

- `subscription-payment`: 套餐订阅的渠道化 Checkout、微信 H5 支付、生产级支付通知、幂等状态变更及查单/关单补偿。

### Modified Capabilities

无。现有 `billing` capability 管理商户月结账单，本变更处理平台套餐订阅收款，不改变 `tenant_bills` 的“仅状态流转”要求。

## Impact

- **依赖**：新增并锁定官方 `wechatpay/wechatpay` PHP SDK。
- **配置与部署**：新增微信 AppID、商户号、证书序列号、微信支付公钥 ID、API v3 Key、通知 URL、H5 网站信息和订单 TTL 配置；生产环境需要只读挂载商户私钥与微信支付公钥。
- **领域与基础设施**：扩展 `PaymentGateway`，新增微信网关、通知验证/解密组件、内部通知 DTO、查单及关单补偿服务。
- **HTTP API**：保留现有订阅 Checkout 响应契约；`POST /api/v1/payments/webhooks/wechat` 按微信协议返回空体 HTTP 204 或明确的 4xx/5xx。
- **数据库**：调整支付订单状态和补偿调度字段，不改变现有支付事件唯一幂等键。
- **运行时**：要求 Queue Worker 与 Scheduler 常驻，并对回调失败率、通知处理延迟、失败队列和超时订单进行监控。
- **文档**：同步 OpenAPI、环境变量示例、部署说明及微信支付运维验收流程。
